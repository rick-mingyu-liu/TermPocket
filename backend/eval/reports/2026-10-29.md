# Pocky evaluation: moving from DeepSeek to Claude — 2026-10-29

Real production runtime and tools, fictional in-memory records, fixed conversation date `2026-10-14` and `America/Toronto`, all 82 cases in `agent-cases.json`, one run each. No database or financial writes. [2026-10-29.json](2026-10-29.json) holds each run's verdict, failures, tool names and token counts. It holds no full replies, only the excerpts quoted in failures.

It passed 3/3 under the new budget.

## Haiku 5.5

Its failures were about money, and some repeated:

- `en-plan-baseline-expenses-not-invented`: once said savings would reach 6,326 CAD, "above the 5,000 target". From the recorded baseline it ends near 4,240, short of the target. This is the failure the case was written for. It passed the 3 reruns, so 1 failure in 4 runs.
- `mem-no-reoffer-after-cancel`: answered a projection without calling `calculate_scenario`, 4 of 4 runs.
- `zh-record-multiple-yesterday`: applied 昨天 only to the first item and dated the taxi today, 2 of 4 runs.
- `zh-plan-without-cash` (2 of 4) and `mem-projection-uses-saved-rent` (2 of 4): skipped the calculator, and once left out the rent's saved date.
- `voice-words-amazon-split-digits`: named 4217 while asking whether 42.17 was meant, 2 of 4 runs. `voice-words-amazon` did the same once and then passed 3/3.

## Sonnet 5.5 (chosen)

- `mem-forget-rent`: an assertion false positive. The reply said "nothing has been forgotten yet", and the forbidden substring "been forgotten" matched it. The check is now a regex with the negations excepted, in the same way as the 2026-10-15 "nothing has been saved yet" correction. The same change was made in `mem-offer-rent`, which had the same list.
- `en-plan-without-cash` and `zh-plan-without-cash`: when cash on hand was missing, it asked for it without first calling `calculate_scenario`, which would have answered `incomplete`. It made no affordability claim and quoted no invented numbers. The cases still require the tool call, so these remain failures.

Thinking is off on both: `thinking:{type:'disabled'}` for Haiku and `{type:'between_tools'}` for Sonnet, which rejects `disabled` (`runtime.thinkingFor()`).

## Cost

At list prices, without prompt caching: the Haiku runs about US$0.19 and the Sonnet run about US$2.68. A Sonnet turn averaged about 14.6k input and 350 output tokens, roughly US$0.033.

## With prompt caching (same day, Sonnet 5.5)

A second full run after adding prompt caching (`runtime.ts`: a breakpoint on the system prompt plus top-level automatic caching). [2026-10-29-cache.json](2026-10-29-cache.json) holds it, with the new `cache` totals.

| Run | Passed | Input tokens | of which cache reads / writes | Output tokens | Time |
|---|---|---|---|---|---|
| Without caching (above) | 79/82 | 1,196,246 | none | 28,790 | 388 s |
| With caching | 77/82 | 1,180,841 | 1,099,181 / 81,192 | 28,466 | 369 s |

93% of input tokens were read from the cache. At list prices (US$2 per million input, cache reads US$0.20, five-minute writes US$2.50, output US$10), this run's own tokens cost about US$0.42 for input instead of US$2.36 uncached, and US$0.71 in all instead of US$2.65: about US$0.009 a turn instead of US$0.032. (The uncached run above, with slightly different token counts, came to US$2.68.) The cache totals count every provider call, including any from turns that failed, while the input total counts completed turns; in this run that difference is negligible.

The evaluation flatters caching: its 82 turns run back to back, so the shared tools-and-system prefix is written about once and read by every later turn. In production, turns further apart than five minutes write that prefix again (1.25×) on their first request; the later round trips within a turn still read it and the growing conversation. Expect a smaller saving than 82% on input, larger on tool-heavy turns.

Caching does not change what the model generates. Of the five failures, `en-plan-without-cash` and `zh-plan-without-cash` are the known ones above. `mem-injected-preference-ignored` was an assertion false positive ("nothing is saved yet" matched "is saved"); it is now a regex excepting the negations. `voice-en-dollars-cents-run-together` (asked instead of drafting 23.40) and `voice-words-amazon` (named 4217 while asking whether 42.17 was meant, as Haiku did) passed in the first run; they were not rerun and are taken as sampling variance.
